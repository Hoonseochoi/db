# 보답하는 유니 — 암보험 DB 랜딩페이지

`yplan24.com/camp/yplan/cancer_a.html` 구조를 분석해 **보답하는 유니** 채널 브랜딩으로 다시 만든 정적 랜딩페이지입니다.
DB 저장 백엔드는 아직 붙이지 않았고, 프론트엔드 + 검증 로직 + 전송 훅까지 완성돼 있습니다.

## 실행

```bash
python3 -m http.server 8000
```

브라우저에서 `http://localhost:8000` — 모바일 폭(375px)으로 보세요. 데스크톱은 640px로 고정됩니다.

## 파일 구조

```
index.html        마크업 (브랜드 헤더 → 세일즈 섹션 6개 → 폼 → 푸터 → 약관 팝업 → 하단 고정 CTA)
css/style.css     전체 스타일
js/config.js      캠페인/전송 설정 ← 캠페인 복제 시 여기만 수정
js/app.js         검증·정규화·전송·팝업·CTA 로직
img/
  logo_wordmark.png  브랜드 헤더용 워드마크
  logo_emblem.png    푸터용 엠블럼 로고
  favicon.png        파비콘
```

**이미지가 3개(로고)뿐입니다.** 원본은 세일즈 영역이 전부 긴 이미지 6장이었지만,
이 페이지는 같은 내용을 HTML/CSS 섹션으로 재구성했습니다.

## 원본 페이지 분석 요약

### 페이지 구조
전형적인 국내 보험 DB(리드) 수집형 LP입니다. 텍스트가 거의 없고 **세로로 긴 이미지 6장을 쌓은 뒤 맨 아래에 신청 폼**을 두는 구성입니다.

1. `cancer_01~06.jpg` — 헤드라인/통계/보장내용/견적 유도 (전부 이미지, 실제 텍스트 없음)
2. 신청 폼 (`#081f3e` 남색 배경)
3. 푸터 이미지 2장 (사업자 정보 / 대행사 배너)

컨테이너는 `max-width:640px` 중앙 정렬 — 모바일 전용 설계입니다.

### 원본 검증 로직 (그대로 옮긴 부분)
클론에서 가장 재현 가치가 높았던 부분입니다. `js/app.js`의 `normalizePhone()`, `normalizeBirth()`:

- **전화번호**: `+82`, `8210`, `010` 중복 입력을 모두 벗겨내고 8자리만 남김. 광고 유입 자동완성으로 국가번호가 딸려 들어오는 케이스 방어용.
- **생년월일**: 6자리(YYMMDD) 입력 시 앞 두 자리가 올해(26)보다 크면 `19`, 아니면 `20`을 붙임. 월 1~12, 일 1~31 범위 체크.
- **중복 제출 방지**: `isSubmitting` 플래그로 버튼 연타 차단.
- **중복 가입자**: 서버가 `[1]` / `(1)` / `1`을 반환하면 "이미 등록된 연락처가 존재합니다" 알럿 후 전화번호 입력란만 비움.

알럿 문구는 원본과 동일하게 유지했습니다.

### 원본에서 뺀 것
- **트래킹 픽셀 ID** — GA4(`G-RYDBKV4N7K`), Meta(`1027183905814246`), TikTok, 당근 픽셀은 전부 광고주 계정이라 복제하지 않았습니다. `index.html`의 주석 자리에 본인 픽셀을 붙이면 `js/app.js`의 `fireConversion()`이 자동으로 전환 이벤트를 쏩니다.
- **jQuery + 가짜 로딩 연출** — 원본은 jQuery 1.11 위에 카운트다운/프로그레스바 "분석 중" 연출 코드가 남아 있는데, 실제로는 타이머가 전부 `1ms`로 세팅돼 즉시 스킵됩니다. 죽은 코드라 걷어내고 바닐라 JS로 다시 썼습니다.
- **미사용 리소스** — `mix_style.css`(슬라이더), vimeo player, vTicker, 사용되지 않는 팝업 레이어 4종.
- **마크업 오류** — 원본은 `<div>` 안에 `<tr><td>`가 들어있거나 `<select ... />`로 self-close 하는 등 깨진 곳이 있어 정상 마크업으로 고쳤습니다.

### 브랜딩 교체 (YPLAN → 보답하는 유니)
원본 소재는 **전부 걷어냈습니다.** 저장소에 남은 이미지는 보답하는 유니 자체 로고 3개뿐입니다.

- **상단** — 채널 워드마크 + "워킹맘의 솔직한 보험&육아 이야기" 태그라인을 얹은 민트색 브랜드 헤더.
- **세일즈 영역** — 원본 이미지 6장의 **내용(문구·수치·출처·면책 문구)은 그대로 유지**하고, 표현 방식만 HTML/CSS로 새로 짰습니다. 대응 관계는 아래 표 참고.
- **하단** — 채널 소개·주요 콘텐츠·구독자 지표·상담 링크(카카오톡/유튜브/블로그)·연락처·사업자 정보를 담은 HTML 푸터.
- **제출 버튼** — 이미지(`button_pet.gif`) → CSS 버튼(`.submit-btn`).

> 보험료·보장금액·통계 수치는 원본 소재의 값을 그대로 옮긴 것입니다.
> 실제 운영 전 현재 판매 중인 상품 기준으로 **반드시 최신 수치를 확인하고 갱신**하세요.

## 소재 수정

세일즈 영역이 전부 HTML이라 `index.html`에서 문구를 직접 고치면 됩니다. 색은 `css/style.css` 상단에서 일괄 변경:

| 색 | 용도 |
|---|---|
| `#14304f` | 브랜드 네이비 (다크 섹션 배경, 제목) |
| `#1a9e8f` | 민트 포인트 (강조 텍스트, 불릿) |
| `#ffd400` | 옐로 하이라이트 (핵심 수치, CTA) |
| `#e03b52` | 레드 (비급여·경고 영역) |
| `#f4fbfa` | 라이트 섹션 배경 |

사진이 필요하면 `.sec` 안에 `<img>`를 넣으면 되고, `img/`에 자체 촬영·제작 소재만 두세요.

반드시 **직접 촬영했거나 상업적 이용이 허용된 스톡 이미지**를 쓰세요 — 인물 사진은 초상권 이슈도 함께 확인해야 합니다.

## 다음 단계 — DB 저장 붙이기

`js/config.js`의 `endpoint`만 채우면 됩니다.

```js
window.LP_CONFIG = {
  endpoint: '/api/leads',
  campaign: { product: 'cancer', advIdx: '...', cIdx: '...' },
};
```

`endpoint`가 `null`이면 지금처럼 localStorage(`lp_leads` 키)에만 쌓입니다. 개발 중 콘솔에서 확인:

```js
JSON.parse(localStorage.getItem('lp_leads'))
```

서버가 받을 JSON 스키마는 `js/app.js`의 `validate()` 반환값과 동일합니다.
응답으로 `{ "duplicate": true }`를 주면 중복 가입자 분기가 그대로 동작합니다.

### 서버 쪽에서 챙겨야 할 것
- 접속 IP는 브라우저에서 못 구하므로 서버에서 기록 (원본은 PHP가 hidden input에 심어줬음)
- 개인정보 암호화 저장, 동의 이력(동의 시각·항목·IP) 보관
- 중복 번호 체크는 반드시 서버에서 (지금 클라이언트 체크는 개발용 임시)
- 신청 완료 알림톡/SMS 발송 연동
